# 2026-09-23-map-result-linkage — 分析结果-地图通用联动（方案 B 矢量叠加）

> 状态：**applied（2026-09-23，e2e 郑州 17/17 + 深圳湾 7/7 / selftest 5 套全绿 29+22+14+8+10 / overlay 面积与报告对账 3.91/4.57 km²，证据见 tasks.md）**

## 背景与动机

第12月 W2 郑州建筑用地变化报告落地后，用户实测发现：报告正常生成，**左侧地图毫无反应**。诊断出两层脱节：

1. **底图硬编码**：`frontend/index.html:146-148` 写死 `szbay_real_mosaic.tif` 与深圳湾 bbox——问郑州时地图连影像都不是郑州的。
2. **结果无回流通道**：gain/loss mask 在 cartography 节点算完后只画进 matplotlib PNG 存报告目录；SSE 仅有 `style`（text_to_map 专用）与 `report`（仅卡片载荷）两条事件，专题分析结果对地图零输出。

explore 阶段三轮 spike（郑州真实数据）还暴露了更深层问题：

- 多边形化性能零压力（0.37s / 23,608 连通区块），但 **93% 的变化面积来自 <3 像元碎斑**（伪变化噪声，印证目视检查发现的沿道路阴影伪变化）——原始报告的 10.16/11.60 km² 大部分是噪声面积，地图化倒逼口径修正。
- 3×3 开运算把面积保持率打到 6.7%（过激）；最小图斑过滤 5px（≥1968 m²）保留 38.5%、1903 图斑、GeoJSON 1 MB（gzip ~260 KB）——可行平衡点。

## 方案概述

**方案 B（矢量叠加）+ 通用协议**：gain/loss mask 经「最小图斑过滤 → 多边形化 → 简化 → 属性注入」管线产出自描述 GeoJSON，落盘后经 `/api/overlays/` 路由 + SSE `overlay` 事件回流前端；前端通用渲染器（fill）+ 图例 + 点击 popup 上图；底图区域联动（scene 事件动态换瓦片源）。

**为什么是 B 不是 A（静态 PNG 叠加）**：B 天然是「分析结果上图协议」而非用地变化专用——GeoJSON + 自描述属性 + legend 数组 + render_hint 可服务时相变化/语义分割/水质分级/污染溯源热点等一切「栅格 mask → 图斑」同构场景；且图斑可点击查询面积（popup 数字与报告可对账）。

**为什么必须双口径**：地图图斑加总要能对上报告数字——主数字改为滤波后口径（与地图同源），指标表保留原始总量并标注碎斑占比（诚实披露）。

## 验收标准

1. 郑州问句全链路后：地图底图自动切郑州影像、gain红/loss蓝图斑叠加、图例（含「疑似建筑用地」限定词）、点击图斑 popup 显示方向与面积。
2. 报告双口径：主数字 = 滤波后（≥min_patch_px 图斑），指标表新增原始总量行（标注碎斑占比）；**overlay 全部图斑面积之和 == 报告主数字**。
3. overlay 事件载荷为通用协议：`{url, fit_bounds, legend[], render_hint}`——legend 后端给语义，前端零领域硬编码。
4. 多轮对话生命周期：新问题开始清旧叠加层，地图始终反映最近一次分析。
5. e2e 双场景全绿：郑州场景加 overlay 断言（事件在场 / geojson 可下载 / 面积一致性）；深圳湾回归 7/7。
6. 全部 selftest 回归通过（thematic / report_engine / text_to_map / symbology / cartography + 新增 overlay selftest）。

## 范围外（non-goals）

- **不做** choropleth / heatmap 渲染器（水质场景真实出现时再加——第三次重复才抽象纪律）
- **不做** spectral_diff 老方法的 overlay 接入（mask 同构，管线留后续变更）
- **不做** 行政边界精确裁剪（bbox 近似维持，前案红旗延续）
- **不做** 大区域 minzoom / 图斑聚合优化（1900 图斑当前规模无压力）
- **不做** 郑州之外的 region preset 扩充（REGION_PRESETS 机制已就位）

## 红旗预登记

1. **min_patch_px=5 是经验参数**（无地面真值标定），语义为「一栋中型建筑起步」；必须进 THEMES 按专题配置——**水域等场景 1-2px 就是真实图斑，禁止全局常量**。
2. simplify 容差单位是度，纬度/经度方向精度差 ~19%（34.8°N）——教学精度可接受，代码注释与报告声明。
3. 双口径使数字闸门档位词需要重新核对（净 -0.66 km² 在旧档位是「轻微」，主口径变化后语义漂移）。
4. GeoJSON 1 MB（gzip ~260 KB）走 fetch 不走 SSE 嵌入；未来大区域需重新评估体积。
5. Mapbox raster source 不可原地改 URL，底图切换需 removeSource/addSource 重建（W4 ids 管理模式复用）。
